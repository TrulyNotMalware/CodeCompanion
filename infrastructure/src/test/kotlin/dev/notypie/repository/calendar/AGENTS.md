## For AI Agents

### Testing Requirements
```bash
./gradlew :infrastructure:test --tests 'dev.notypie.repository.calendar.*'
```
Adapters are built by hand over the autowired `Jpa*` repositories (`JpaConfiguration` is not loaded in a
`@DataJpaTest`), so their `@Transactional` annotations do not apply. Flush before asserting a derived delete; the
bulk JPQL purge needs no flush. Kotest's Spring extension wraps each leaf `then` in a rolled-back test transaction
and runs `given`/`when` bodies without one: rows written there are committed and visible to every later scenario,
so use distinct user ids per scenario. Native updates inside one `then` leave already-loaded entities stale in
that transaction's persistence context — act in the containers, or `entityManager.clear()` before reading back.
In `JpaMeetingCalendarEventRepositoryTest` acting in the containers is also required: the worker transitions
(`claim`, `markSynced`, `deleteSynced`, `releaseWithoutEvent`, `retryLater`, `markFailed`, `resetStuck`) throw
inside the `then` blocks' test transaction by design.
