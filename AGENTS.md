# CodeCompanion

## Purpose
CodeCompanion is a Kotlin + Spring Boot Slack bot for side-project teams. It turns Slack slash
commands, app mentions, and interactive components (buttons, dropdowns, modals) into event-driven
workflows — meeting orchestration, standup automation, CVE watch/notification, and an AI assistant
lane — backed by a transactional outbox, Debezium CDC, and Kafka so nothing is lost between Slack
and the database.

The repository is a Gradle multi-module build with a DDD-inspired three-layer structure. Dependencies
flow **application → infrastructure → domain** (and **application → domain**) and never the other way.

## For AI Agents

### Working In This Directory
- **Never break the layering.** `domain` must not import Spring, Jakarta, JPA, Jackson, Gson, or the
  Slack SDK. `DomainLayeringGuardTest` scans the domain source set *and* the test runtime classpath
  and fails the build on violations — including fully-qualified inline references and Slack
  vocabulary identifiers (`responseUrl`, `triggerId`).
- **Do not add dependencies to the root `subprojects` block** unless every module — `domain`
  included — should get them. Jackson is deliberately declared per-module for this reason.
- Dependency versions live in the root `ext { }` block (`kotestVersion`, `slackSdkVersion`,
  `mockkVersion`, `springBootVersion`, `jacksonVersion`, `kotlinLoggingVersion`, `springAiVersion`).
  Bump them there, not in module build files.
- `gradle.properties` is **git-ignored** and generated by `./gradle-config/apply.sh`. If a Gradle
  daemon/memory setting must change for everyone, edit `gradle-config/gradle-*.properties`.
- The `io.spring.dependency-management` plugin is intentionally absent — see the comment above
  `subprojects` in `build.gradle.kts` before reintroducing it.

### Testing Requirements
```bash
./gradle-config/apply.sh        # first-time setup: writes gradle.properties for this OS
./gradlew build                 # full pipeline: compile + ktlintCheck + tests
./gradlew :domain:test          # module-scoped while iterating
./gradlew :application:test
./gradlew :infrastructure:test
./gradlew ktlintCheck           # lint only (CI runs this on feature/* pushes)
./gradlew ktlintFormat          # autofix
```
Integration tests are self-contained: `EmbeddedKafka` + H2, no external infrastructure needed.
Tests run on JUnit Platform with `-Xmx4g` and `--add-opens` for `java.base/java.lang` and
`java.base/java.util` (MockK requirement) — configured once in the root build.

### Common Patterns
- **Kotest `BehaviorSpec`** (`given` / `when` / `then`) is the default test style; `StringSpec` is used
  for guard-style tests. MockK for mocking.
- Each module publishes `src/testFixtures/kotlin/` factories via Gradle `java-test-fixtures`, consumed
  cross-module as `testImplementation(testFixtures(project(":domain")))`.
- Logging is kotlin-logging: `private val log = KotlinLogging.logger {}`.
- Kotlin compiler args are strict: `-Xjsr305=strict`, `-Xjvm-default=all`,
  `-Xannotation-default-target=param-property`. Annotation targets on constructor properties resolve
  to `param-property`, so `@field:` prefixes are usually unnecessary.
- Commit subjects follow `.gitmessage`: `feat : ...`, `fix : ...`, `refact : ...` (space before the colon).

## Dependencies

### External
- Kotlin 2.4.0 / Java 25 (Adoptium toolchain) — language and runtime
- Spring Boot 4.1.0 — Web on **Jetty** (Tomcat excluded; Undertow unsupported on Boot 4), Actuator,
  AOP/AspectJ, Data JPA
- Apache Kafka (`spring-boot-starter-kafka`) + Debezium CDC — outbox relay
- MariaDB (runtime) / H2 (local + tests) — persistence
- Slack Java SDK 1.49.0 — `slack-api-client`, `slack-api-model`, `slack-app-backend`
- Jackson 3 (`tools.jackson`, BOM 3.2.0) — serialization, application/infrastructure only
- Spring AI 2.0.0 — MCP server starter (streamable HTTP on `/mcp`)
- Kotest 6.2.0 + MockK 1.14.11 — testing
- ktlint 14.2.0 — formatting/lint gate

### External Services
- Slack Events API / Socket Mode (`socket` profile) — inbound transport
- [agent-sidecar](https://github.com/TrulyNotMalware/agent-sidecar) — claude/codex backend over HTTP+SSE
- NVD and GitHub Releases — CVE collection sources
