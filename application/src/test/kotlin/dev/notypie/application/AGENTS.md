# test/kotlin/dev/notypie/application

## Purpose
Root package of the module's specs. Each subpackage tests the production package of the same name under
`src/main/kotlin/dev/notypie/application/`. Run everything with `./gradlew :application:test`, or one
package with `./gradlew :application:test --tests 'dev.notypie.application.<package>.*'`.

## Key Files
| File | Description |
|------|-------------|
| `AgentTurnShutdownContextTest.kt` | Boots the real application (`SpringApplicationBuilder(CodeCompanion)`, no web, its own H2 with `DB_CLOSE_DELAY=-1` and `ddl-auto=create` so the tables outlive the context) with one turn slot, a 1 s shutdown wait and an `AgentGateway` singleton that blocks; one mention turn runs, one mention turn is queued, a delivered `/ask` question is announced with `MessageDeliveredEvent` (queued behind them), `AgentTurnIntake.stop()` is called, a second `/ask` question is announced, then the context closes. Three cases read the database over plain JDBC after the close: exactly one outbox row for the queued mention, carrying `OVERLOADED_MESSAGE` — the discard notice is written while the context is closing; the queued `/ask` turn has no notice row (only its question row) and its `agent_ask_turn` row is `PENDING` with attempt 0; the `/ask` question delivered after the executor stopped taking turns is left the same way |
| `ApplicationContextSmokeTest.kt` | `@SpringBootTest(webEnvironment = NONE)` with `@DirtiesContext` (its scheduled jobs stop when the spec ends) of the real application on H2 with the default polling relay and in-process events; `MessageDispatcher` is a relaxed `@MockkBean` so the poller never calls Slack. The real-caller paths of the two repository methods that refuse an active transaction: `CveTopicBootstrap.bootstrapTopics()` over the context's `CveTopicRepository` writes its topic, and `MeetingReminderSchedulingService.materializeReminders()` arms the 5-minute reminder of a meeting 8 minutes away (fails when `materializeReminders` is made `@Transactional`).;
